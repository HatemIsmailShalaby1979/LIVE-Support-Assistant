# Simulated tenant brief

**data_mode: "simulated"** — everything described here is fictional evaluation
data. No real customer, tenant, ticket, or organisation is represented.

## There is no design partner

There is no design partner, no pilot customer, and no external organisation
associated with this work. None supplied data, reviewed output, or is referenced
anywhere in the repository or its reports. The Phase 7 comparison was defined as
a cross-check against a partner's anonymised examples; with no partner that
comparison does not exist, and no document claims it.

Everything the evaluation uses is either synthetic (generated by this
repository) or public wording quoted from public help centres and public forums
(see `tooling/eval/simulated-tenant/real-phrased-queries.csv`). Nothing
simulated is deployed to production, and nothing simulated is presented as a
customer outcome.

## What the simulated tenant is

**WaveCast Creator Care** is a fictional live-streaming and creator-commerce
support operation, described in
`tooling/eval/simulated-tenant/client-brief.md`: 120 frontline agents, about
1,600 daily tickets, four languages, and a seven-procedure policy corpus in
`tooling/eval/simulated-tenant/corpus.json`.

The corpus and every ticket are tagged `data_mode: "simulated"`. Run-specific
tenants, users, SOP version notes, devices, query events, escalations, browser
banners, and reports created during the deployed-path run carry the same tag.

## What was run against it

| Artefact | What it is |
| --- | --- |
| `chaos-500.json` | The pinned 500-ticket batch (seed `20260928`, 75 chaos-tagged tickets) |
| `corpus.json` | The seven-procedure fictional policy corpus |
| `phase5-label-fix-margin-017.json` / `.md` | Local rescore with the `expectedOutcome` label fix, before and after |
| `phase5-deployed-run-0aec9773442c4282.json` / `.md` | Deployed-path run against the development Supabase project |
| `real-phrased-queries.csv` | Real support questions quoted from public sources, labels pending |
| `my-floor-queries.template.csv` | Template for the operator's own frontline patterns |

The deployed path targets the **development Supabase project**, not a customer
production backend. It is deployed-path validation, not production-customer
evidence.

## What is not claimed

- No production readiness, and no production accuracy, adoption, or reliability.
- No partner validation, because there is no partner.
- No independent human labelling of the synthetic batch: expected decisions come
  from the same generator and corpus, so the evaluation is in-sample.
- No low failure rate. The measured failure rate is 27.6% locally and 27.8% on
  the deployed path, and one unsafe answer is measured and unfixed in shipped
  code.
- No shipped threshold change. The 0.17 margin is an evaluation-harness value;
  the shipped default is 0.18.

The full statement of what the exercise proves and does not prove is in
[`proof-of-concept.md`](../proof-of-concept.md).

## Offline labeling tool

Open `tooling/eval/simulated-tenant/label-tool.html` in any browser — no network or install needed.
Load `real-phrased-queries.csv` (or your copied `my-floor-queries.csv`) and label each query:
`A` answerable → pick `1`–`7`, `E` escalate, `M` ambiguous, `S` skip, `Backspace` back.
Progress saves to your browser's localStorage after every key; use "Add my own query" to build floor queries and "Export CSV" to download them.
Nothing is pre-filled, suggested, or auto-labeled.
